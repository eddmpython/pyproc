# Contract reality - contract versus actual (tracked continuously)

A living ledger that continuously tracks the gap between "what the contract says in the docs" and "what actually runs that way". When a gap is found it goes into this table first; when it is filled the row is deleted. Development principle 4 (from the ground up: measure, then contract, then implement) points at this table.

This table lives in persistent docs because standing policy must remain beside the shipped contract.
It is consulted whenever the engine version moves or a capability changes.

## Open debt (what needs filling now)

| Item | Contract | Actual | Next action |
|---|---|---|---|
| The global patch window costs boot concurrency | Two machines boot independently | The default boot always carries a core trust anchor, so it always opens the core-asset cache window, and that window is a single tab-wide chain because it swaps `globalThis.fetch`. Two concurrent `boot()` calls therefore overlap only partially: the browser gate measures 1.59x the single-boot wall clock for two at once (2.0x would be fully serial, 1.0x fully parallel). The window is not removable as-is - it exists because two concurrent global swaps restore each other's patch - so the cost is a property of the fetch-interception design, not a defect to patch away | Either intercept core-asset fetches without a global swap (an engine-level loader hook), or accept the cost and keep it measured. The gate records the ratio on every run so a regression toward 2.0x is visible |
| The legacy journal generation reader | The journal writes one on-disk format | The writer has been single since the state-kernel rebase, and the old root `HEAD.json` v2/v3 path is read-only. It now lives alone in `src/capabilities/journal/journalLegacyGeneration.js` so retiring it is one file deletion, but it is not dead weight yet: `pack`/`prune` compute live keys as the **union** of kernel and legacy generations, so an un-migrated journal still depends on it. Removing that branch deletes live blobs, which the browser gate now proves by refusing to recover | Retire the file once an un-migrated journal can no longer plausibly exist in the field. That judgement needs a release boundary, so it belongs to the next breaking release rather than a refactor |
| Implicit FFI/fetch assumptions | Survives an engine swap or update | Direct `toJs` is isolated to PyodideEngine alone, and the host contract is `proxyMode`/`fallback`. EngineContract validates version, kind, and capabilities at construction, and WASI and Pyodide share a minimum RuntimeContract | A new engine must pass both `tests/contracts/runtimeContract.mjs` and browser measurement |
| Reactive and %undo memory | Safe even in long sessions | A resident base is a foundational premise. `history.stats()` and the retention budget observe base, delta, hash, and node pressure, and off-path branches can be auto-pruned. There is still no automatic rebase of the live path | Collect pressure events from real long-lived workloads and judge a safe-rebase design as its own initiative |
| The GPU subpath has no headless execution gate | Every shipped public surface has the strongest automated evidence the runner can provide | Edge headless still returns `null` from `requestAdapter()` with the repository's SwiftShader switches, so CI verifies every registered WGSL kernel and the exact shader bytes handed to WebGPU but cannot verify GPU result values. The socket subpath no longer shares this debt: `test:socket` starts the in-repo relay and local TCP origin hermetically in CI | Keep GPU under the Experimental freeze and the evidence ceiling explicit until a runner with a real adapter is available |
| Handles that enter the heap without `setGlobal` | The image-portability refusal sees every JS handle in the heap | The count sits on the engine's `globals.set`, which is where the shipped wrapper mints one, and a structure gate now fixes the set of places that may call it (the engine itself, plus the worker kernel that has no `Runtime` wrapper and writes no image). Two paths remain outside any count and cannot be brought inside: guest Python can `import js` itself, and `rt.raw` hands out the engine by design for `deviceFs`-class uses. So the refusal is a floor for shipped surfaces, not a proof about arbitrary guest code | State that boundary wherever the guarantee is quoted. Closing it entirely needs engine-level accounting of handle allocation, which is upstream work |
| A portable image and a blocking surface | `snapshotScope: "portable"` means a machine image revives and keeps working | A JS handle is interpreter-local and cannot cross an image: measured across thirteen bisected cases, a kernel revived from an image whose seed installed one traps on every proxy path, including handles the revived kernel mints itself. The packet port and the permission jail were moved to value boundaries (pure Python plus bytes and literals through `run()`), so they cross intact. What cannot move is a **blocking** surface - the syscall bridge behind `input()`, sockets, GPU - because blocking Python on a JS answer needs a handle by construction. `exportImage` and `save` now refuse such a heap with `PYPROC_IMAGE_PROXY_SURFACE` and name the surfaces, and `{ allowHostProxies: true }` is the explicit acknowledgement: the revived kernel keeps its plain Python state and loses those surfaces | Either an engine-level way to rebind handles after materialisation, or a blocking mechanism that needs no handle. Until one exists the refusal is the contract, and the browser gate holds both directions (refused by default, and the acknowledged path still works) |

## Standing re-verification (highest priority when bumping a version)

| Item | Contract | Actual | Re-verification trigger |
|---|---|---|---|
| Pyodide snapshot API | Snapshot-fork | `_makeSnapshot`/`_loadSnapshot`/`makeMemorySnapshot` are underscore (experimental) Pyodide APIs. Safe only through the version pin (v314.0.2). The serializer still assumes the current hiwire bootstrap slots, and the browser snapshot/fork gates hold that boundary | Whenever the Pyodide version changes. ## Documented tradeoffs (intended contracts)

| Item | Tradeoff | Stated condition |
|---|---|---|
| `PYTHONHASHSEED=0` always pinned | The deterministic boot path (internal `bootSession`) hardcodes it, and CPython reads it once at interpreter initialization, so **hash randomization is off for the whole session** (defeating the hash-flooding mitigation from CVE-2012-1150). V8 solves the same problem by fixing the seed at build time and rehashing with a fresh seed at deserialization, but CPython has no rehash facility, so determinism and seed freshness cannot both be had | Under the threat model the damage is confined to your own session in your own tab, and only for workloads that bulk-load external input as dict keys. Replay determinism is the core of this library, so the tradeoff is taken and stated |
| Three global stubs | The entropy/time swap (session boot) and the fetch swap (the wheelCache install window) are restored in a `finally`, but they are visible to concurrent work inside that window | Concurrent boots are forbidden: `runExclusive` in the internal `bootSession` serializes session boots. Stated in the public contract docs |
| ReactiveController.saveBase | Only backs up or moves the base; RAM does not shrink, because the restore path assumes a resident base. The memory valves are pruneTo and dispose | Comments and types corrected to say backup/move (2026-07-16). A real offload (per-page file restore) conflicts with the synchronous restore contract and is not started |
| The WASI session value bridge | JSON-serializable only (no FFI). Functions, numpy arrays, and live objects cannot cross | A separate async surface (bootWasi). Pyodide is the production canon (the runtime-consistency section of [contract.md](../usage/contract.md)) |
| machineJail parent isolation | The CSP connect-src blocks the jail's own network egress, but a same-origin jail leaves a `window.parent` side channel open | Full isolation means an opaque origin (sandbox), and the price is losing crossOriginIsolated, hence SharedArrayBuffer, hence fork and interrupt - so a jailed machine is a single Runtime |
| One memcpy for shared memory | A SAB cannot be exposed into the Python heap with zero copies (the single-linear-memory wall) | `PyProc.shm` and `mapArray` keep "one memcpy" as a public contract |
| The Immortal Python Machine recovery boundary | It does not revive an arbitrary moment's execution stack and in-flight external requests; a new leader continues execution from the heap plus `/home/web` of the last completed commit | The [normative state table](../usage/contract.md#durable-rpc-state-table-normative) separates the branches. A durable controller that can prove its session is proxy-free parks and re-sends the same request ID once; a normal follower cannot inspect the leader session, so forced leader loss is `PYPROC_RPC_OUTCOME_UNKNOWN` with `retryable=false`, as the installed-package browser gate proves. Live-leader timeout and caller loss are also never resent. A product must not create a new request ID for the same command without an explicit idempotency policy |

## Frontier (the honest wall is WASM dlopen)

- Warm fork (cloning after package load with zero re-imports), true shared-memory threads (nogil), and zero-copy numpy between processes are all blocked on one unsolved problem: WASM dlopen plus cross-instance and cross-thread memory sharing. That is an upstream research problem, not "a few weeks of building".
- pyproc (independent interpreter workers plus message passing) avoids exactly that problem. Each worker owns its own wasmTable, heap, and glue, so there is no dlopen mismatch. That is why this is the highest reachable point today, and why the frontier is a wall rather than a stepping stone.
- The map of four states per capability (achieved today / workaround available / waiting on upstream / permanent wall) is canonical in "The four states of a capability" in [docs/product/vision.md](../product/vision.md).
