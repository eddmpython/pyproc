# Initiative operating lessons

## Contents

- Purpose
- Durable lessons

- Completion boundary

## Purpose

Keep only reusable operating lessons from completed initiatives. Current plans remain in `mainPlan/`, experimental
evidence remains in `tests/attempts/`, and detailed history remains in Git.

## Durable lessons

1. Make repository-wide migrations one integration transaction when parallel ownership would create two control planes.
2. Freeze current sources, inbound references, exact assertions, and negative fixtures before moving content.
3. Promote reusable tooling before copying production source into a new ownership tree.
4. Preserve every normative heading through a moved, merged, generated, historical, or removed-invalid disposition.
5. Treat package, installed consumer, MCP, website, and source parity as one digest chain.
6. Convert repeatable failures into minimized conformance fixtures before changing routing or policy.
7. Keep plans sequential. Finish implementation, product gates, knowledge ownership, and physical deletion before moving on.

## Promotion boundary

An initiative may graduate only when the public source, executable gates, package surface, and current authored knowledge
agree. A successful probe alone does not make a capability shipped. A plan is never evidence for current behavior.

## Completion boundary

Delete the completed `mainPlan/<initiative>/` and matching attempt directory in the same cycle. Confirm both physical paths
are absent and run the full repository gate after deletion. Preserve the reasons and verification in Git history rather
than an archive directory.
